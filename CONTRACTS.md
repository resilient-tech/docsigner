# Protocol Contracts

Frozen interfaces between the 5 components. Change these only by editing this file first; every component builds against what's written here.

Protocol version: 1. All binary values are base64 strings unless stated otherwise.

---

## 1. REST API (signer-server)

Base path `/api`. JSON in, JSON out. Errors use HTTP 4xx/5xx with body:

```json
{ "error": { "code": "SESSION_EXPIRED", "message": "human readable" } }
```

Error codes: `DOCUMENT_INVALID`, `CERT_INVALID`, `SESSION_NOT_FOUND`, `SESSION_EXPIRED`, `SIGNATURE_INVALID`, `PROFILE_UNSUPPORTED`, `INTERNAL`.

### POST /api/signatures

Start a token-signing session.

Request:

```json
{
  "document": "<b64 PDF>",
  "certificate": "<b64 DER cert of the chosen signer>",
  "options": {
    "profile": "B-B | B-T | B-LT | B-LTA",
    "field_name": "Signature1 (optional, autogenerated if absent)",
    "reason": "optional",
    "location": "optional",
    "appearance": {
      "page": 0,
      "box": [72, 72, 272, 122],
      "text": "Signed by {signer}\n{ts} (optional, this is the default)",
      "image": "<b64 PNG, optional>"
    }
  }
}
```

`appearance` absent = invisible signature. `box` is PDF points, `[x1, y1, x2, y2]`, origin bottom-left.

Response 200:

```json
{
  "session_id": "<urlsafe random, 32 chars>",
  "to_sign_hash": "<b64, digest of the CMS signed attributes>",
  "digest_algorithm": "sha256",
  "expires_at": "2026-07-05T12:34:56Z"
}
```

### POST /api/signatures/{session_id}/complete

Request:

```json
{ "signature": "<b64 CMS-ready signature value>" }
```

Response 200:

```json
{ "document_id": "<id>", "download_url": "/api/documents/<id>" }
```

Sessions are single-use and expire after 15 minutes.

### GET /api/documents/{document_id}

Returns the signed PDF, `application/pdf`. Documents expire after 1 hour.

### POST /api/sign-server-side

Signs with the server-held key (`.p12` from config). No session dance.

Request: `{ "document": "<b64 PDF>", "options": { same as above } }`
Response: `{ "document_id": "...", "download_url": "..." }`

### POST /api/validate

Request: `{ "document": "<b64 PDF>" }`

Response:

```json
{
  "signatures": [
    {
      "field_name": "Signature1",
      "valid": true,
      "intact": true,
      "trusted": false,
      "signer": "CN=...",
      "signing_time": "2026-07-05T12:00:00Z",
      "profile_notes": "optional free text"
    }
  ]
}
```

## 2. Native messaging protocol (extension ↔ host)

Chrome native messaging framing (4-byte LE length prefix + UTF-8 JSON) on stdio. One request, one response, matched by `id`.

Request: `{ "id": "<string>", "command": "<name>", "params": { } }`
Success: `{ "id": "<same>", "result": { } }`
Error:   `{ "id": "<same>", "error": { "code": "<CODE>", "message": "..." } }`

Error codes: `USER_CANCELLED`, `PIN_INCORRECT`, `PIN_LOCKED`, `TOKEN_NOT_FOUND`, `CERT_NOT_FOUND`, `MODULE_ERROR`, `UNSUPPORTED`, `INTERNAL`.

### getVersion

Result: `{ "version": "0.1.0", "protocolVersion": 1 }`

### listCertificates

Params: `{}` (host scans all configured PKCS#11 modules).

Result:

```json
{
  "certificates": [
    {
      "thumbprint": "<SHA-1 of DER, lowercase hex>",
      "certificate": "<b64 DER>",
      "subject": "CN=John Doe, O=...",
      "issuer": "CN=Some CA",
      "validFrom": "2025-01-01T00:00:00Z",
      "validTo": "2027-01-01T00:00:00Z",
      "keyType": "RSA | EC",
      "tokenLabel": "ePass2003",
      "moduleName": "libcastle.so"
    }
  ]
}
```

### signHash

Params:

```json
{
  "thumbprint": "<hex>",
  "hashes": ["<b64 digest>", "..."],
  "digestAlgorithm": "sha256"
}
```

The host prompts for the PIN itself (native dialog). PINs never cross this protocol. All hashes in one call are signed within one PKCS#11 session: one PIN prompt for a batch.

Result: `{ "signatures": ["<b64>", "..."] }`

Signature values are CMS-ready: PKCS#1 v1.5 block for RSA (host wraps digest in DigestInfo, mechanism `CKM_RSA_PKCS`), DER-encoded `ECDSA-Sig-Value` for EC (host converts the raw r||s from `CKM_ECDSA`).

## 3. Page ↔ extension bridge (content script)

Page dispatches on `window`:

```js
window.dispatchEvent(new CustomEvent("org.opensigner.request", {
  detail: { requestId: "<string>", command: "<name>", params: {} }
}));
```

Content script replies on `window`:

```js
new CustomEvent("org.opensigner.response", {
  detail: { requestId: "<same>", result: {...} }   // or error: {code, message}
});
```

Commands are the native protocol commands plus `ping` (result `{ "installed": true, "version": "..." }`, answered by the extension without touching the host). Extra error codes at this layer: `EXTENSION_NOT_INSTALLED` (ping timeout, raised by signer-js), `HOST_NOT_INSTALLED`, `ORIGIN_DENIED` (user rejected the consent prompt).

First `listCertificates` or `signHash` from an unknown origin triggers the extension's consent prompt. The decision is remembered per origin.

## 4. signer-js public API

Single file, no dependencies, ES module + IIFE build. Global name `OpenSigner`.

```js
const signer = new OpenSigner();

await signer.init({ timeout: 2000 });       // rejects: EXTENSION_NOT_INSTALLED
const certs = await signer.listCertificates();  // array from §2, same fields
const { signatures } = await signer.signHash({
  thumbprint, hashes: [hash], digestAlgorithm: "sha256"
});
```

All rejections are `OpenSignerError` with `.code` from the codes above. Nothing else in the API. Server calls (start/complete) are plain `fetch` in application code; the demo shows the wiring.

## 5. Names

- Native messaging host name: `com.opensigner.host`
- Host binary name: `opensigner-host` (`.exe` on Windows)
- Page bridge events: `org.opensigner.request` / `org.opensigner.response`
- Extension IDs go into the host's native messaging manifests at install time; installers keep them in one place (a template variable), never hardcoded in code.

## 6. Shared conventions

- Digest algorithm default: `sha256`. Values allowed: `sha256`, `sha384`, `sha512`.
- Thumbprint: SHA-1 over the DER certificate, lowercase hex, no separators (matches what users see in Windows cert manager).
- Timestamps in JSON: ISO 8601 UTC.
- Component versions are independent; `protocolVersion` guards compatibility.
