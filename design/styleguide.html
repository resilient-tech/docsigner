DocSigner Design system

The instrument, not the app

A signature is a claim of identity that cannot be taken back. This system is built to feel like a legal instrument: exact, quiet, permanent. Hairlines instead of shadows, small radii, one accent lit at a time, and no ornament that does not carry information.

Dark — default, unchanged

The machine's view. Ink ground, hairline rules, one accent lit at a time. This is the tool, and it already worked.

Paper — the second scheme

Warm stock, ink text, almost no blur, because paper lies flat. Replaces the cool blue-grey light map. This is the artifact.

Every open-source signing product ships a light UI with a blue accent. Dark stays the default because it is the differentiator. Paper is not an inverted dark — if it ever reads as "light mode", it has been built wrong. Toggle the switch above and watch what the page does.

Foundations

Ground

Five depths. Recessed to raised. Everything else sits on one of these.

Text

Contrast is computed live from what your browser actually rendered, against --raised in dark and --well in Paper — the worst ground in each theme. Anything under 4.5 is a bug.

Four hues, total

The plain token is a fill and carries --on-accent. The -ink token is text, borders and icons, darkened for Paper where the fill would drop to 1.7:1. Write -ink for text and the plain token for fills and a component is correct on both themes with no media query. The system already did this for mint and blue; amber and red are new, and red is a check that did not pass, and nothing else.

The paper swatch

Theme-independent on purpose. A rendered page and a signature preview are pictures of paper, and paper does not have a dark mode. In the dark theme this is the one bright object on screen — the artifact, lit, on the workbench.

Components

Button

Heights 32 / 38 / 46. One primary per view — it is the signing action. Danger is never a red fill; a red fill in this system means a verification failed.

B-LTA B-B

Tab into these — one focus ring, everywhere, never removed. The inner band is the ground colour so it stays visible on the mint fill.

Control

Focus takes the ring, not a border-colour change.

Card

A person signs

The key stays on their USB token. They pick a certificate, type their PIN in a dialog on their own machine, and the token signs 32 bytes.

A system signs detected

The key sits on your server as a .p12. One HTTP call, no extension, no PIN.

Selected is one edge — border-color — not a border plus a 1px ring drawing the same line twice.

Rules

Do
  • Write -ink for text, the plain token for fills.
  • Put a size shared by two components in layer 3, not in both.
  • Run check-contrast.py after touching a colour.
  • Let the density knob handle "this feels too big in the app".
Don't
  • Use --red for anything except a check that did not pass.
  • Write --font-brand anywhere except .brand.
  • Add a fifth hue. Four is the budget, and it is why the fourth lands.
  • Add a shadow to a card, or invent a fourth breakpoint.
